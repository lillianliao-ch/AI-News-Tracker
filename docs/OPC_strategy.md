# OPC 一人公司操作系统：战略锚点文档

> 本文档是所有规划与执行的根基。在做任何架构决策、Sprint 规划时，必须先回到这里校准方向。

## 🎯 核心目标

> **搭建一套属于自己的"一人公司操作系统"，让我一个人能干出一个团队的活，并且换赛道时不用从零开始。**

Lilian 是一个独立的 AI 猎头，同时在探索 OPC（One Person Company）这条路。猎头是当前的核心变现业务，但目标不是永远只做猎头——而是构建一套可复用的底层基础设施，让猎头只是跑在上面的第一个应用，未来能快速孵化其他业务方向。

## ⚙️ 执行方法论（铁律）

> **自上而下的规划 + 自下而上的行动。在行动中发现规划中的问题，不停调整优化规划，再行动。**

1. **从业务倒推基建，而不是从基建正推业务。** 猎头是现在能赚钱的业务。所有基建都从猎头业务的真实痛点倒推——业务哪里疼，就在那个点上向下挖一层基建，挖完立刻回来继续做业务。
2. **不为了做 OPC 体系搞一大套然后发现用不上。** 每一步都要能立刻验证，每一块基建都必须被当前业务实际使用。
3. **一个人的优势是迭代极快。** 没有团队协调的摩擦成本，规划是地图而非施工蓝图，随时可以根据行动中的发现来修正方向。
4. **四层框架是思维模型，不是施工图纸。** 不需要填满所有层级，只在业务需要时才向下挖掘。

## 🏗️ 四层思维模型

```
┌─────────────────────────────────────────────────┐
│  Layer 4: 垂直业务应用                            │
│  猎头主系统 + 外挂插件群（第一个 App）               │
├─────────────────────────────────────────────────┤
│  Layer 3: Agent 框架层                           │
│  数字员工注册中心 / 状态监控 / 记忆存储 / Token 管控  │
│  各 App 可用不同的 Agent 实现，但统一在此管理         │
├─────────────────────────────────────────────────┤
│  Layer 2: 算法支撑层                              │
│  共享基础设施（向量库实例、大模型 API 网关）           │
│  具体算法逻辑由各 App 自行实现                       │
├─────────────────────────────────────────────────┤
│  Layer 1: OPC 基础盘（内容 + 渠道 + 运营中控）       │
│  UCO：全网信息采集 → 大模型加工 → 多渠道分发          │
│  通用能力，不专属任何业务                            │
└─────────────────────────────────────────────────┘
  ↕ 事件总线（Event Bus）：贯穿所有层的数据通信管道
```

### 各层的边界

| 层级 | 职责 | 不做什么 |
|------|------|---------|
| **L1 基础盘 (UCO)** | 统一采集数据火源、内容加工、多渠道分发、调度监控大盘 | 不做业务判断 |
| **L2 算法支撑** | 提供共享重型资源：向量库实例、模型调用网关、限流管理 | 不含业务逻辑 |
| **L3 Agent 框架** | Agent 注册/生命周期管理、统一记忆存储、状态看板、Token 监控 | 不锁死具体框架 |
| **L4 业务层** | 业务逻辑、专属算法、专属 Agent、专属 UI | 不重复造基建轮子 |

### 数据流通模式

数据火源统一在 L1 (UCO) 中采集，通过事件总线广播，各业务 App 作为消费者按需订阅。
