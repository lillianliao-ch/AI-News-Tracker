## 🎯 匹配引擎优化

- [x] **T5**: 审查现有匹配策略 — 引擎本身设计成熟(14维评分+同义词+跨池惩罚)，根因是标签碎片化(已修)
- [x] **T6**: 候选人批量打方向标签 — 本地强校验收敛，已用严谨漏斗将 5.8 万存量数据强制归并入 16x36 万能坐标系，剔除衍生冗余词
- [x] **T7**: 实现两级漏斗匹配器 — 先按方向硬过滤（砍 90% 噪音），再在小池子里软排序
- [x] **T8**: 动机标签体系设计与自适应匹配引擎 (Data-Density-Aware Matching)
  - 核心痛点解决：克服了以前“短简历被惩罚、长简历分虚高”的缺陷。引入了 `density_mode` (sparse / rich / academic) 机制。针对只有零星标签的稀疏候选人（如脉脉外联），开启 70% 标签权重的强保护模式；针对极度丰富的开源大牛，强制压制降权至 70 封顶并归为“学术/开源线索”。
  - 多意图网关 (`intent`)：将匹配入口重构，提供 `actionable_outreach` (极其苛刻 L1 阻断拦截掉所有不相关的"算法大帽子")，`explore_broad` (放水给跨界候选人)，`academic_mining` (纯针对外部高维学术库)。
