# 🤖 LLM 大语言基础模型招聘风向洞察报告

## 1. 【核心技能栈与工具】底层技术要求频率分析
根据收集到的 JD 
统计，大模型岗位的技术栈已从单纯的“模型训练”转向“训-推-算-工”全栈优化。以下是提及频率最高的底层技术与框架
：

*   **编程语言：** **Python**（绝对核心 
[1-3]）、**C++/Go/Java**（主要用于应用后端、高性能推理架构或插件开发 [4-6]）。
*   **深度学习框架：** **PyTorch** 是主流（几乎所有 JD 提及 [1, 2, 7, 8]），部分提及 TensorFlow [7, 9]。
*   **训练与分布式优化框架：** **DeepSpeed**、**Megatron-LM**、**Ray**（用于大规模分布式训练 [8, 
10]）以及针对 RL 的 **verl**、**OpenRLHF**、Slime [2, 3, 10, 11]。
*   **推理引擎与部署：** **vLLM**（高频 [2, 3, 10, 11]）、**SGLang** [10, 11]、Speculative Decoding 
[11]、KV Cache 优化 [11]。
*   **核心算法范式：**
    1.  **Post-training (SFT, RLHF/DPO/GRPO)：** 提及频率最高，是目前模型效果对齐的核心 [2, 7, 8, 10, 
12]。
    2.  **Reasoning & Scaling：** 强调推理能力提升、思维链 (CoT) 与长文本 (Long Context) 处理 [7, 8, 
13]。
    3.  **Agentic RL / Tool Use：** 将大模型作为智能体，强调工具调用与任务拆解能力 [2, 5, 13, 14]。
    4.  **RAG (检索增强生成)：** 结合向量数据库解决幻觉问题，主要出现在应用侧岗位 [5, 6, 15]。

## 3. 【人才画像分级】核心分水岭要求
针对不同层级的岗位，JD 表现出了明显的阶梯式要求：

*   **初级/基础级 (1-3年)：**
    *   **分水岭：** **扎实的 Coding 能力与 NLP 基础**。
    *   要求熟悉 PyTorch，具备基本的数据结构功底，参与过 SFT 或简单模型微调项目，能解决基本的 bad case 
[5, 19]。
*   **高级/专家级 (3-5年+)：**
    *   **分水岭：** **独立主导“端到端”的技术闭环**。
    *   要求能主导从问题建模、高质量数据工程、算法设计到实验验证的全流程 [2, 14]。在顶会（NeurIPS, ICLR 
等）发表过论文或有高影响力开源项目被视为核心竞争力 [8, 10, 14]。
*   **架构师/领军专家级：**
    *   **分水岭：** **系统级视野与前沿无人区探索能力**。
    *   
需要定义下一代模型架构（如“训练-采样”解耦系统），建立科学的评测体系，或在“自我进化”、“终身学习”等无人区寻
找确定性方案 [11, 13, 19]。

## 4. 【隐性要求与排雷点】
JD 背后隐藏了一些对求职者的特定期望及“减分项”：

*   **显性加分，实则看重：**
    *   **数据直觉 (Data Insight)：** 许多 JD 提到“数据治理”和“合成数据” [2, 8]。JD 
普遍不再只看模型调参，而是看你能否从中数据中发现让模型突破的 insight [20]。
    *   **工程感知：** 纯算法研究如果不考虑工程性能（如推理延迟、MFU）在应用型专家岗中可能不加分 [11, 
20]。
*   **隐性排雷点（可能不加分或排斥）：**
    *   **只会调包/调 API：** 明确排斥仅有 API 调用经验而缺乏对底层原理（如 RL 训练稳定性、Reward Hacking
问题）深度理解的人员 [20, 21]。
    *   **Benchmark 依赖症：** 如果只满足于优化已有的 Benchmark 
榜单，而不能解决真实业务中的“低幻觉”模型交付或复杂推理问题，在顶尖岗位中竞争力较弱 [7, 20]。
    *   **沟通与协作壁垒：** 由于 LLM 
项目通常涉及算法、数据、工程、产品的紧密配合，缺乏跨团队协作意识和需求拆解能力者会被明确淘汰 [6, 14, 
21]。

Agentic 智能体的工程化落地**以及**在垂直领域（如研发、广告）的实际价值产出**。
