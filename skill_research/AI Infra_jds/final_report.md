# 🤖 AI Infra 招聘风向洞察报告

## 1. 【核心技能栈与工具】底层技术要求排行榜

根据对所有 JD 的统计，AI Infra 
岗位的技术要求呈现出高度的趋同性，核心围绕**“压榨硬件性能”**与**“支撑超大规模集群”**展开。以下按提及频率
和重要性排序：

1.  **编程语言：C/C++ 与 Python 的双剑合璧**
    *   **C/C++**：用于底层系统开发、高性能算子实现及执行引擎优化，是 Infra 工程师的底层成色 [1-4]。
    *   **Python**：主要用于算法对接、框架开发及自动化工具链 [1, 5, 6]。
    *   **Go**：在云原生、调度系统及平台级开发中频繁出现 [4, 7-9]。

2.  **高性能计算与通信库（加速基石）**
    *   **CUDA/Triton**：几乎所有涉及 GPU 优化的岗位都要求精通 CUDA 编程，Triton 
作为新一代算子开发语言提及率极高 [1, 4, 5, 10]。
    *   **NCCL/RDMA/NVLink**：千卡/万卡互联背景下，网络通信协议与拓扑优化是分布式训练的核心瓶颈 [1, 3, 9,
11]。

3.  **大模型主流框架（生态标配）**
    *   **训练端**：**Megatron-LM** 与 **DeepSpeed** 是绝对的主流，涉及 3D 并行（DP/TP/PP）策略的实现 [1,
3, 5, 12]。
    *   **推理端**：**vLLM**、**TensorRT-LLM** 和 **SGLang** 提及频率最高，关注 KV Cache 
管理、连续批处理等技术 [2, 5, 13]。

4.  **AI 编译优化（前沿高地）**
    *   **TVM、XLA、MLIR** 是目前 JD 中最常提到的编译器技术栈，旨在通过计算图优化提升异构硬件利用率 [1, 
3, 10, 14]。

## 2. 【主流业务落地区域】代表性公司需求侧重点对比

虽然各家都在招 AI Infra，但在具体业务落地上存在显著的差异化路径：

| 公司维度 | 代表场景与业务重心 | 基础设施技术侧重点 |
| :--- | :--- | :--- |
| **阿里集团 (通义/阿里云/淘天)** | **全栈生态与“AIOS”**：涵盖电商、搜索、云计算 [1, 12, 14]。 | 
**宏观架构与软硬协同**：主导下一代 AI 原生操作系统 (AIOS) 的架构设计 
[15-17]。强调端云协同、异构资源（CPU/GPU/NPU）的智能调度与算力池化 [10, 11, 15]。 |
| **MiniMax (AI 独角兽)** | **大模型服务化 (MaaS)**：专注于高性能模型推理与全球化部署 [9, 13]。 | 
**稳定性与极致性价比**：极度关注大规模推理场景下的**稳定性体系**设计、容灾及混沌工程 [7, 13]。强调 IaaS 
层的根本性创新以降低 TCO（总拥有成本） [18, 19]。 |
| **小红书 (智创技术团队)** | **创作发布与 AIGC**：搜广推、多模态（Diffusion, VLM）及用户工具 [2, 10]。 |

20]。同时注重端侧（Mobile）AI 的性能优化（如 MNN/NCNN） [20, 21]。 |

## 3. 【人才画像分级】职级核心分水岭

通过对比不同职级的 JD 要求，可以看出从“工具使用者”向“标准定义者”的跃迁：

*   **初/中级工程师（执行层）**
    *   **硬指标**：扎实的算法与数据结构功底，具备 ACM/ICPC 等竞赛获奖背景者极受欢迎 [3, 4, 21]。
    *   **要求**：熟练掌握 PyTorch/TensorFlow，能使用 CUDA 编写高性能算子，具备解决具体性能瓶颈的能力 [1,
2, 14]。

*   **架构师/资深专家（决策层）**
    *   **硬指标**：通常要求 8-10 年以上系统架构经验 [15, 16]。
    *   **要求**：具备**系统性思维**，能从零到一搭建复杂架构 
[18]。需主导过亿级用户规模或万卡集群的架构设计 [5, 22]。
    *   **核心分水岭**：不再局限于单一框架的优化，而是能**定义标准**（如设计 AIOS 
内核、规划服务器硬件路标），并能在“灵活性 vs 性能”、“通用性 vs 定制化”等矛盾中做出技术决策 [8, 15, 19, 
23]。

## 4. 【隐性要求与排雷点】

在分析大量 JD 后，发现了一些普遍存在的**隐性偏好**与**避坑指南**：

*   **【隐性加分项】**
    *   **社区影响力**：在 Megatron、DeepSpeed、TVM 
等开源社区有持续代码贡献，或有高质量技术博客、顶会论文（OSDI/SOSP/MLSys）是极大的加分项 [3, 20, 24]。
    *   **硬件敏感度**：仅懂软件优化已不够，深刻理解计算机体系结构、GPU 部件（HBM, Tensor 
Core）及高速网络拓扑的候选人更受青睐 [5, 10, 19]。

*   **【排雷点：看似亮眼实则不加分】**
    *   **只会“调包”与“微调”**：JD 明确排斥只懂调用 API 或仅有模型微调经验的候选人，Infra 
岗位要求深入内核（Kernel）实现 [1, 2]。
    *   **缺乏稳定性意识**：在 Infra 
领域，单纯的性能跑分（Benchmark）提高若以牺牲稳定性为代价，在真实业务中是不被认可的。JD 
中多次强调“稳定性治理”、“容灾”与“可观测性” [7, 13, 25]。
    *   
**纯学术化的研究经验**：除非是顶级实验室背景，否则缺乏真实大规模生产环境（如亿级用户并发、千卡联调）洗礼
的经验，在实战派公司（如字节、阿里、MiniMax）中吸引力有限 [21, 22, 26]。
