# 多模态赛道招聘风向报告 (2024-2026)

## 前言：多模态大模型的「工业化」拐点
当前多模态大模型（MLLM）已从实验室的「打榜」阶段全面转向商业化落地与工程化深水区 
[1-4]。招聘需求显示，行业正在经历从单模态拼接向原生全模态（Omni/Unified）的范式演进，核心诉求从「能理解
」转向「能推理、能生成、能行动（Agentic）」[5-8]。

---

## 1. 模型框架与工具栈：底层技术的统一要求
根据对数百份 JD 提及频率的量化分析，目前行业要求的底层技术栈呈现高度集中的态势。

### 1.1 训练与推理框架（提及率 > 85%）
*   **PyTorch（绝对主流）：** 几乎所有算法及工程岗位均要求精通 PyTorch [7, 9-13]。JAX 
虽有提及，但多见于研究导向岗位 [14-17]。
*   **Megatron-LM & DeepSpeed（分布式基石）：** 
面向千卡乃至万卡集群的大规模分布式训练，这两者是目前业界处理并行策略（TP/PP/ZeRO）的标准工具 [16, 
18-22]。
*   **vLLM & SGLang（推理部署标配）：** 随着推理成本成为商业化瓶颈，对 vLLM、SGLang 
等高性能推理引擎的二次开发及优化能力成为刚需 [20, 23-27]。

### 1.2 多模态核心架构（提及率 70%-80%）
*   **理解架构：** 熟悉 CLIP、BLIP、LLaVA 等经典跨模态对齐方案是基础 [28-30]。
*   **厂商自研/开源：** 对 Qwen-VL (阿里巴巴)、Llama (Meta)、InternVL (上海 AI 实验室) 
的二次开发经验是核心竞争力 [29-34]。
*   **生成的对齐：** 扩散模型（Diffusion Model）与自回归模型（AR）在视频、图像生成中的结合应用 
[35-38]。

### 1.3 工程优化与底层通讯（提及率 50%-60%）
*   **算子优化：** CUDA 编程、Triton 算子开发，用于压榨硬件性能（如 FlashAttention 优化）[18, 20, 
39-43]。
*   **高性能通讯：** 熟悉 NCCL、RDMA、IB 协议，解决大规模训练中的通讯瓶颈 [18, 21, 28, 44-47]。

### 1.4 Agent 与工作流（新兴必考点）
*   **开发框架：** LangChain、LlamaIndex、AgentScope 或自研 Agent 引擎 [11, 13, 31, 48-54]。
*   **核心机制：** Function Calling、RAG（检索增强生成）、上下文工程（Context Engineering）[52, 
55-59]。

## 3. 工程 vs 算法：谁是更稀缺的「黑客」？

结合 JD 分析，行业已从「算法优先」转向 **「工程与算法 Co-Design（协同设计）」**，但目前 
**「工程黑客」** 的稀缺性在某些维度上已超过传统的算法科学家。

### 3.1 「算法科学家」的门槛升高（但岗位相对饱和）
*   **论据：** 绝大多数算法岗位要求 CCF-A 类顶会（CVPR, NeurIPS, ICLR 
等）发表，甚至要求第一作者或高引论文 [15, 28, 32, 78-82]。
*   **现状：** 纯理论研究的坑位在收缩，大厂更倾向于「能快速实现 Paper -> Code -> Solution」的复合型人才
[31, 74, 83]。

### 3.2 「工程黑客」成为Scaling Law的决胜点
*   **论据：** JD 
大量出现「万卡规模分布式训练实战经验」、「修改框架源码」、「手写高性能算子」、「显存墙问题解决」等硬核
要求 [12, 18, 21, 22, 43, 45, 84, 85]。
*   **现状：** 在 Scaling Law 持续生效的当下，能够保证千卡/万卡集群长时间稳定运行（MTTR 
治理）并进行极致性能压榨的「工程黑客」是各家高薪争抢的对象 [22, 28, 47, 86-88]。
*   **结论：** 
**底层架构优化的「工程黑客」目前更稀缺**，因为这类人才需要跨越「计算机体系结构」与「深度学习算法」两座
大山 [22, 42, 89]。

## 4. 红牌排雷点：哪些背景会被普遍「排斥」？

通过对加分项与必备项的对比，可以反推目前 JD 不看重或明确排斥的情况：

1.  **拒绝「PPT 规划」与「纯理论派」：**
    *   **红牌点：** 只会写文档、做方案设计，但不能「躬身入局」写代码或调优算法 [90-92]。
    *   **排雷：** 现代 JD 频繁提及「Hands-on」、「Vibe Coding」、「代码级交流」[51, 52, 91, 93-96]。

2.  **排斥「单模态孤岛」经验：**
    *   **红牌点：** 长期深耕纯文本或纯视觉，拒绝拥抱「多模态对齐」与「理解-生成统一」趋势 [6, 7, 
97-99]。
    *   **排雷：** 即使是后端工程师，也被要求了解「多模态数据解析」或「Agent 编排」[48, 55, 100, 101]。

3.  **缺乏「数据意识」与「评测闭环」：**
    *   **红牌点：** 认为数据清洗和标注是琐碎工作，不具备从评测结果反推模型短板的能力 [3, 60, 
102-106]。
    *   **排雷：** 「数据驱动迭代」和「自动化评测体系建设」是几乎所有高阶算法岗位的核心职责 [3, 102, 
104, 107-110]。

4.  **无「大模型实操」的传统 AI 背景：**
    *   **红牌点：** 简历中只有传统机器学习、小模型（CNN/RNN）经验，从未参与过 Transformer 架构模型的 
Pre-train、SFT 或 RLHF [12, 18, 111-113]。
    *   **排雷：** 即使是初级岗位，也普遍要求「熟悉 LLM/VLM 基本原理」[11, 112, 114, 115]。

## 总结建议
**多模态大模型赛道已进入「全栈黑客」时代。** 成功的候选人应具备：
1.  **极强的工程动手力：** 能写 Kernel、能调并行框架、能做 Vibe Coding [22, 42, 91]。
2.  **深厚的算法直觉：** 理解 Scaling Law 的边界，对 Reward Hacking 有敏感度 [8, 116, 117]。
3.  **敏锐的业务触觉：** 知道如何将模型 Token 转化为真实的商业 ROI [53, 91, 93, 118]。
