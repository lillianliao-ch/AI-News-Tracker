项目拆解
负样本利用：基于级联数据流的负样本个性化调权召回
项目简介：召回侧需要充分利用推荐链路的负样本，根据链路通过率进行了负样本的个性化调权
项目方案：
1. 补充整体链路负样本：从 easy to hard 在推荐系统从全局随机到粗精排各个阶段进行采样
2. 建模链路通过率：参考 ESIM 的思路，增加预估粗精排进入率的全连接辅助网络建模。由于粗精排样本基于采样数据
正负样本比例不均衡，辅助网络使用 focal loss。
3. 负样本个性化调权：参考 IPV 的思路，使用粗精排通过率对粗精排负样本进行了个性化调权。
用户兴趣覆盖：基于兴趣循环的用户兴趣覆盖
项目简介：召回侧不仅需要尽可能多的覆盖用户兴趣(宽度)，还需对各兴趣提供丰富的候选(深度)
技术方案：
1. 生成式短期兴趣 U21 (兴趣兴趣)
最初版本我们参考短期兴趣优先模型 STAMP 框架，从最近一个 session 中提取短期兴趣表征，并参考 DIN 机制在
user emb 增强提取出的短期兴趣表征；后续为了提升短期兴趣的准确性，我们基于 diffusion 模型在 user targ 生成了
target 信息，并将 target 融入 session 序列中一起建模并增强，落地了海外第一个生成式召回。
短期兴趣覆盖率 +5.7pp(66.7→72.4%)，设备均时长+0.365%
2. PDN U21(长尾兴趣)
落地并适配海外改进了端到端 U2121 建模的 PDN 模型。PDN 是阿里在电商场景落地的模型，而短视频场景 photo
embedding 使用特征简单包含的信息不像电商场景那么充分。所以我们做了如下改进：TriggerNet 通过 self-
attention 提取每个用户行为序列交互的上下文信息增加了 trigger score 准确性、SimNet 侧我们使用利用
的 action 信息和 target 信息基于双塔去学习共现，替代原论文中的使用共现次数等统计特征的方案。f
取模型结合 trigger 多样性策略增加用户长尾兴趣候选。
有效消费一级垂类个数+1.635%，设备均时长+0.839%
3. Memory U21(长期兴趣)
落地基于 Memory 的长期兴趣召回。由于我们的数据流包含 SIM 特征(与 target 相似的历史消费表征)，通过 Memory
Network 利用外部记忆模块存储用户长期兴趣，将数据流中的 SIM 特征通过 attention 的形式写入 memory slot，保障
模型快速收敛。根据 memory slot 生成长期兴趣表征，同时利用近期播放通过 transformer 抽取短期兴趣表征，最终
使用门控网络对长短兴趣表征作加权和得到用户表征。采用使用 Mixed Negative Sampling 方案缓解了召回的样本
选择偏差问题。
长期兴趣 vv 占比+2.3pp，设备均时长+0.263%

海外 prerank 模块搭建&模型迭代
项目负责人(贡献70%)
业务思路：随着召回的迭代召回量超过 1w，前链路需要对候选集进行排序
• 由于链路带宽限制，能够返回给粗精排的候选集个数有限，随着召回的迭代，前链路逐渐需要一个排序模块保障
召回间的合理竞争。
• 负责从 0 到 1 搭建了预截断(prerank)阶段，建立前链路特色的“排劣”体系。
项目拆解
召回链路优化：从系统层面联合架构组重构召回去重，过滤，排序逻辑，节省了算力
prerank 模型迭代：选出到消费的二跳级联建模
1. 级联退出建模：通过级联数据流学习粗精排两级透出的多级级联双塔。对于级联目标，需要学习粗精排的排序信
息。我们在 loss 侧按照样本的阶段对全部样本分段，并通过自适应 margin 的 pairwise loss 进行全局序信息建模；
同时 prerank 的主要工作是“排劣”，所以针对截断附近的中腰部样本，利用 listwise loss 进行局部序信息的精细化区
分。也基于上述提到的负样本自动调权方案充分利用了链路样本。
2. 消费时长建模：基于“排劣”目标，根据粗精排预估值作为代理指标，设计个性化时长正负反馈 label，并对时长
duration bias 大的目标，通过 debias 增进行 duration 消偏
3. 多目标建模优化：由于 prerank 阶段需要同时建模透出目标(全链路样本)和消费目标(曝光空间样本)，模型采用了并
联 MMOE 结构，使用了级联 experts，曝光 experts，share experts 这三类专家网络进行不同样本空间建模。同时
由于 prerank 各个目标样本覆盖率和正负样本率差异都很大，使用了对 loss 做几何变换的方式，缓解了各个目标收
敛速度差异大的问题。
prerank 机制迭代
1. 排序公式：设计前链路特色“排劣”机制，单 pxtr 通过值序变换增加中腰部区分性，多 pxtr 通过“与或门”机制
进行“排劣”组合。
2. 生态调控：增加 boost 分数控制框架以及保底框架，适配业务生态调控需求并合理管控

项目一：物流AI答疑机器人-ToB Copilot
• 项目背景：ToB大模型主要以AI助手为载体，希望可以借助繁琐的知识库、操作手册、技术文档等知识和信息，从简单的自动化答疑助手，发展为智能化和个性化的“高级助理”，为商家、内部I2、研发人员提供个性化帮助和解决方案
• 项目价值：上线服务20+钉钉群，千牛商家平台灰度中，覆盖商家1w+；日均答疑1.2W
• 技术方案：
○ 偏好对齐：
■ 常规链路：结合数十万条垂类场景数据+通用数据集（防止适用能力退化），通过lora/ptuning等SFT开源基础模型，结合人工偏好数据进行DPO训练后，利用embedding similarity、gpt4、人工打分进行多维评测，答疑准确率约85.6%
■ ORPO：将SFT+DPO调整为在SFT阶段引入人类偏好惩罚来直接进行偏好对齐优化，提升答疑准确率5.2%
○ RAG：
■ 文本库构建：多源数据切分存储，利用Raptor树状结构把内容通过语义逻辑聚类组合，chunk数量经过阈值递归总结
■ 知识检索：尝试基于规则、知识图谱的改写方案；结合关键词、embedding等多维检索和召回结果，重排取top知识
■ 模型生成：借鉴chain-of-note，预先对检索的知识做进行“笔记梳理和提取”，过滤噪声信息，提升1.3%回答准确率
○ 提示增强BPO：预训练领域prompt优化llm，利用小参数模型对query进行个性化prompt优化，提升答疑准确率1.8%
○ Text2API：利用reflexion框架的自我反思机制，解决langchain自用react框架上，中文llm识别api参数幻觉严重、调用链路长且无反馈机制的问题，提升api识别准确率约4.1%
项目二：CCO物流小客服文答疑-ToC Copilot
• 项目背景：对于文本+图片混合的提问场景，传统答疑机器人采用知识理解+知识库召回链路，难以对消费者问题提供准确方案，咨询转入工率高，进线投诉多，消费体验差
• 项目价值：引入多模态llm，完成端到端在线答疑能力升级，提升问题&诉求识别准确率5pt（77%-82%），降低转入工率0.5pt（22.6%-22.1%）
• 技术方案：
○ 意图识别：利用有监督微调的vit进行图像预分类(准确率93%)，根据图片类别将用户query路由到对应的图文理解方案中
○ 信息增强：
■ llm总结和提取历史对话信息，进行文本query改写和提炼，剔除无效信息，缩短输入tokens约73%
■ OCR+文本清洗进行图像内容识别和梳理，用类COT的思路完成任务拆解和噪声剔除
■ bpo+llm进行prompt改写和优化，结合先验知识和实时语义，控制输出来降低幻觉
○ 图文理解：参考lava架构对VLMs（qwen-v/glm4v）完成领域有监督sft，dsize模型在定制化场景中保证准确的可
项目三：VOC消费者原声诊断-LLM情感分类

• 项目价值：搭建逆向场景年化挽回资损450W；家装家电服务质量诊断场景年化挽回资损约870W等
